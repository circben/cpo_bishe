根据你的开题报告，我将整个毕设工作分为六个阶段，每个阶段的目标和具体工作描述如下（不包含代码，只说明你需要做什么）：

---

## **第一阶段：环境搭建与基础验证**

**目标**：配置好开发环境，确保能成功加载大语言模型并完成基础推理，为后续数据构建打下基础。

**你需要做的工作**：
1. 安装操作系统必要的软件：Git、Python（通过Anaconda管理）。
2. 创建独立的 Conda 环境，并安装 PyTorch（与你的 RTX 3050 显卡驱动匹配的 CUDA 版本）。
3. 安装 Hugging Face 生态的核心库：Transformers、Datasets、Accelerate、PEFT、TRL 等。
4. 安装数据处理和可视化库：Pandas、NumPy、Matplotlib、NetworkX 等。
5. 安装 bitsandbytes 以实现 4-bit 量化（让你的 4GB 显卡能跑 7B 模型）。
6. 在 Hugging Face 上注册账号，申请 LLaMA2 等模型的访问权限，获取 Access Token。
7. 编写简单的测试脚本（不要求保存），验证 PyTorch 能识别 GPU、Transformers 能加载 TinyLlama 或 LLaMA2 并生成文本。
8. 将当前环境导出为 `environment.yaml` 文件，便于日后恢复。

**本阶段结束标志**：你可以顺利调用大模型（即使是 TinyLlama）并看到输出。

---

## **第二阶段：数据构建模块（核心，耗时最长）**

**目标**：为三个任务（GSM8K、StrategyQA、PrOntoQA）分别运行 ToT 搜索，构建出 CPO 所需的偏好数据集。

**你需要做的工作**：

### **2.1 任务与数据集适配**
- 下载三个数据集到本地 `data/` 文件夹：
  - GSM8K 使用 `datasets` 库下载。
  - StrategyQA 同样用 `datasets` 下载，若没有现成的测试集，自行按比例划分训练/测试。
  - PrOntoQA 从你解压的 `generated_ood_data.zip` 中选择一个合适的 JSON 文件（如 `2hop_AndElim_random_noadj.json`），读取其中的 `test_example` 作为数据源。
- 为每个任务设计“思维分解方式”：
  - GSM8K：每一步是一个中间数学表达式（如“剩余数字：4,4,10；下一步：10-4=6”）。
  - StrategyQA：每一步是一个推理子问题或事实陈述（如“首先需要查找...”、“根据事实A可推出B”）。
  - PrOntoQA：每一步是一个新推导出的逻辑事实（如“Sally is a numpus.”）。

### **2.2 实现 ToT 搜索框架**
- 设计树节点数据结构，能存储节点状态、父节点、子节点、思维内容、评估分数、是否为终止节点等信息。
- 实现思维生成函数：给定当前节点状态，调用 LLM 生成 k 个候选思维（k=5）。
- 实现状态评估函数：对每个候选思维，调用 LLM 给出评分（1-10 或 likely/impossible），可多次采样取平均以降低噪声。
- 实现 BFS 搜索主循环：
  - 从根节点（原始问题）开始，逐层扩展。
  - 每层对当前所有节点生成候选，评估后保留评分最高的 n 个节点（n=5）。
  - 设定最大深度（如 5 层），并定义终止条件（例如 GSM8K 中出现“The answer is”）。
- 在搜索过程中，将每个节点的完整信息（节点ID、父节点ID、状态、思维、评分、深度、是否终止等）持久化保存为 JSON 文件。

### **2.3 并发加速**
- 由于 LLM 调用次数巨大（约 200 个问题 × 5 层 × 5 候选 × 2 次评估 ≈ 5000 次），必须使用多线程并发调用。
- 实现线程池并行处理同一层节点的生成和评估任务，避免串行等待。

### **2.4 成功路径识别**
- 搜索结束后，遍历所有节点，找出从根节点到正确终止节点的路径。
- 如何定义“正确”？对 GSM8K 可比较最终答案与标准答案；对 PrOntoQA 可检查最终结论是否与 query 一致；对 StrategyQA 可比较 yes/no 答案。

### **2.5 偏好数据提取**
- 对每条成功路径上的每个中间节点（根节点除外）：
  - 将该节点标记为偏好思维。
  - 找出其父节点下所有未被选中的兄弟节点（即被剪枝的节点），标记为不偏好思维。
  - 生成一条训练样本：`(原始问题, 父节点状态, 偏好思维, 不偏好思维)`。
- 将样本写入 JSONL 文件，每条记录包含 `input`（原始问题）、`prefix`（历史步骤）、`chosen`、`rejected` 以及可选的分数。

### **2.6 质量控制**
- 过滤掉评分过低（如 < 3）的正负例。
- 过滤掉 `chosen` 和 `rejected` 过于相似的句子（避免无效对比）。
- 统计生成的正负例数量，确保每个任务至少有数千对样本。

**本阶段结束标志**：为每个任务生成了至少一个 JSONL 文件，包含数千条偏好数据。

## **第三阶段：模型训练模块**

**目标**：用上一阶段生成的偏好数据，通过 DPO 损失微调基础模型，得到优化后的 CPO 模型。

**你需要做的工作**：

### **3.1 加载基础模型**
- 选择 LLaMA2-7B 或 13B 作为基座模型。
- 使用 4-bit 量化加载，以适配你的 4GB 显存。

### **3.2 配置 LoRA**
- 为模型添加 LoRA 适配器，设置合适的秩（如 r=8），将可训练参数量控制在 1% 以内。

### **3.3 准备训练数据**
- 读取之前生成的 JSONL 文件，将其格式化为 `DPOTrainer` 需要的格式：每条数据包含 `prompt`（原始问题 + 历史步骤）、`chosen`、`rejected`。

### **3.4 设置 DPO 训练参数**
- 确定超参数：β 值（初始可设为 0.1）、学习率（DPO 通常 5e-6）、batch size（通过梯度累积达到 32）、训练轮数（4 轮）、早停策略等。

### **3.5 执行训练**
- 使用 TRL 库的 `DPOTrainer` 开始训练。
- 监控训练损失，保存中间 checkpoints。

### **3.6 保存微调后的模型**
- 训练完成后，保存 LoRA 适配器权重，便于后续推理加载。

**本阶段结束标志**：得到了一个微调后的 CPO 模型，可以在推理时以 CoT 方式运行。

## **第四阶段：推理评估模块**

**目标**：全面评估 CPO 模型的性能，并与多个基线方法对比，同时完成消融实验。

**你需要做的工作**：

### **4.1 实现推理方式**
- 对测试集的问题，使用标准 CoT 提示（“Let's think step by step”）引导模型生成，采用贪心解码，不进行任何搜索。

### **4.2 实现基线方法**
- **CoT**：直接用基础模型（未微调）进行 CoT 推理。
- **Self-Consistency**：采样 40 条 CoT 路径，投票选出最终答案。
- **TS-SFT**：仅用成功路径微调一个对比模型（可用 SFT 方式）。
- **原始 ToT**：运行完整的 ToT 搜索（可在少量测试样本上评估，记录延迟）。

### **4.3 收集评估指标**
- **准确率**：根据任务不同，分别计算精确匹配（GSM8K）、二分类准确率（StrategyQA）、最终答案准确率和推理路径准确率（PrOntoQA）。
- **推理延迟**：记录每个样本的平均生成时间（秒），对比不同方法。

### **4.4 执行消融实验**
- **偏好数据构造方式对比**：分别用“所有兄弟节点”和“仅最低分节点”作为不偏好数据训练两个模型，对比准确率。
- **β值影响**：测试多个 β 值（如 0.05、0.1、0.5、1.0），观察验证集性能变化。
- **训练数据规模**：从 50 到 200 个原始问题逐步增加训练样本量，绘制学习曲线。

### **4.5 保存评估结果**
- 将所有评估结果（准确率、延迟、消融数据）以 JSON 或 CSV 格式保存，供可视化模块使用。

**本阶段结束标志**：得到了完整的评估数据表格和图表原始数据。

## **第五阶段：可视化分析与成果展示模块**

**目标**：将 ToT 搜索过程和性能对比结果可视化，生成论文和答辩所需的图表。

**你需要做的工作**：

### **5.1 ToT 搜索过程可视化**
- 读取数据构建阶段保存的节点信息，为每个问题绘制思维树结构图。
- 用不同颜色区分成功路径（绿色）和被剪枝节点（灰色或红色）。
- 在节点上标注评分和关键思维摘要。
- 输出静态图片（PNG/SVG）并挑选典型案例制作动态演示（如 HTML 交互图）。

### **5.2 性能对比可视化**
- 绘制准确率对比柱状图：在同一张图上显示 CoT、Self-Consistency、TS-SFT、ToT、CPO 的准确率。
- 绘制推理延迟对比图：展示各方法的平均延迟。
- 绘制消融实验曲线：
  - 偏好数据构造方式：两组柱状图。
  - β值影响：折线图，标注最佳点。
  - 训练数据规模：学习曲线。

### **5.3 全局统计图表**
- 统计所有问题的树结构特征（平均节点数、成功路径长度、评分分布等），绘制箱线图或直方图。

**本阶段结束标志**：得到一套完整的图表集，可直接用于毕业论文和答辩 PPT。
